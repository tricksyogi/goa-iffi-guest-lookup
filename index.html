Team list & passwords

  • The team list lives in the sheet itself, in a tab named Team with four columns: Name | Mobile | Date of Birth | Role (Role is Admin or Member).

  • Enter the Date of Birth with a full 4-digit year (e.g. 15-08-1992 or 1992) — a two-digit year like “15-08-92”, or a blank or unreadable Date of Birth, means that member cannot log in until it is corrected to a full 4-digit year.
  • The admin manages the team list — from Admin view → “Team members” (needs the webhook below), or by adding rows directly in the sheet's Team tab. Mobile numbers must be unique — the mobile number is the login key (names may repeat).

On success the tool shows the member's new password (the birth year from the new Date of Birth) and reloads the roster. If no webhook is set, edit the Date of Birth in the sheet's Team tab directly instead.
  • Forgot the PIN / stuck on the login screen: tap Reset login on this phone below the login form and confirm — this clears the saved login and any PIN set on this phone for both events (CMOT and IFFI), then shows the fresh login form. It does not clear either event's sheet link, webhook URL, or loaded guest data.
  • Resetting a password does not change the light-login limit — anyone who knows a member's mobile number and birth year can still log in as them; the reset only changes which year works.
  • If there is no Team tab yet, only the admin (Yogesh) can log in, with the PIN set on first login on that phone. Once a team list exists, the roster rule applies to everyone, including Yogesh.

Sorting & filters

  • Sort (above the guest list): “Pickup time: earliest first” is the default — guests are ordered chronologically by date + pickup time together, so a 10:00 AM pickup on 18 Nov comes before a 09:00 AM pickup on 19 Nov. “Pickup time: latest first” reverses that order, and “Guest name: A–Z” sorts alphabetically by name (case-insensitive). Guests with a blank or unreadable pickup time always sort last in the time sorts — they are never dropped by sorting alone.
  • Pickup time range: set From and/or To (24-hour times) to keep only guests whose pickup time in the sheet falls in the range — both ends are included. This is the sheet pickup time, not the driver's 1-hour-early time. If To is earlier than From, the range wraps past midnight (for example 10:00 PM–02:00 AM keeps late-night and early-morning pickups). Setting only one end makes it an open-ended bound (From only = from that time onwards; To only = up to that time). Guests with a blank or unreadable pickup time are hidden while a range is set and come back when the range is cleared.
  • Hotel and Airport filters: each dropdown lists every hotel / airport present in the currently loaded data (plus “All hotels” / “All airports”), and is rebuilt on every reload, so a new hotel or airport added in the sheet appears by itself. All filters compose — search, location, type, date, hotel, airport, time range and sort all narrow the same list, the count above the list always shows how many guests match, and your filters and sort stay in place across the 30-second auto-refresh and Refresh now. Clear resets everything — search, location, type, date, hotel, airport, time range and sort — back to the defaults.

Your sheet data stays as you gave it

This tool never deletes or rewrites guest rows or team-list rows it did not create. The only things it ever writes to the sheet are: a new row appended to the Remarks tab when someone adds a remark, a new row appended to the Live Locations log, the Live Location Link on the vehicle rows you point it to, a new row appended to the Team tab when the admin adds a member, deleting exactly the one Team row the admin removes, and updating only the Date of Birth cell of the one Team row whose password the admin resets. Everything else in the sheet is only read, never changed.

Fixed format — message to driver (line-wise)

Sent line by line — one field per line, in this exact order, as “Label: value”. A line is omitted when its value is blank (for example, no flight for a shuttle, or no remark). The preview, Copy and Share all use this same line-wise text. Department comes from the Designation column (the CMOT “Department” column), and Remark comes from the Remark column. Pickup Time in the driver message is shown one hour before the time in the sheet — the driver is told to report one hour early. Everywhere else in the tool (the guest message, the detail view, search cards and location lists) you, the member, always see the actual sheet time, unchanged. Under the driver message preview in the detail view, a small note shows both times so you can see exactly what the driver was told; that note is never part of the message sent, copied or shared to the driver.

Guest Name: {Guest Name} Department: {Designation} Date: {Date} Pickup Time: {Time} Hotel: {Hotel} Remark: {Remark} Pickup Point: {Pickup Point}

Copy Full Details is for members only: it copies the raw field dump of the guest's row, including the guest's phone number and flight number — never paste it to a driver. For anything a driver receives, use the driver message above (Copy for Driver / WhatsApp Driver), which leaves those out.

Fixed format — message to guest (line-wise)

Sent line by line — one field per line, in this exact order, as “Label: value”, after the welcome line. The first line is the event-aware welcome: “Welcome to Goa for IFFI 2026!” for IFFI, or “Welcome to Goa for CMOT 2026!” for CMOT. A line is omitted when its value is blank; with no vehicle assigned, the Vehicle Number, Driver Name and Driver Number lines are omitted entirely. The preview, Copy and Share all use this same line-wise text.

Welcome to Goa for IFFI 2026! Guest Name: {Guest Name} Contact Number: {Phone} Pickup Time: {Time} Flight No.: {Flight No} Hotel: {Hotel} Vehicle Number: {Vehicle No} Driver Name: {Driver Name} Driver Number: {Driver Contact}

WhatsApp number check: before a WhatsApp Guest or WhatsApp Driver link is built, the number is normalised — non-digits are stripped, a leading 91 is stripped if the number has 12 digits, and a leading 0 is stripped if it has 11 digits — and it must then be exactly 10 digits. Only then is the link built as wa.me/91 plus those 10 digits, with the line-wise message as the text. If the number is missing or invalid (too few digits, too many digits, or not a number), no WhatsApp link is built from the bad value: the WhatsApp button is disabled and the detail shows “No valid WhatsApp number — check the contact number in the sheet.” The message preview and Copy still work for such a guest — only the WhatsApp link is gated. The same check applies to the driver number for the WhatsApp Driver button.

  8. If the webhook was deployed before admin password reset was supported, redeploy the same Apps Script project as a new version so the updateMember action goes live (Deploy → Manage deployments → Edit → Version: New version) — otherwise the old code keeps running and password resets will not save, and the tool will show the redeploy-as-new-version error instead of claiming success. On success setVehicleStatus returns {ok:true, updated:1} and the tool only claims success when it receives exactly that. If the webhook was deployed before vehicle status was supported, redeploy the same Apps Script project as a new version (Deploy → Manage deployments → Edit → Version: New version) — otherwise the old code keeps running, vehicle statuses will not save to the sheet, and the tool will show the redeploy-as-new-version error instead of claiming success. Log in with your mobile number (10 digits) and your year of birth as the password (4 digits, e.g. 1995), exactly as the admin has listed them in the team list. Both are checked against that list — a mobile number that is not in the list, or a wrong year of birth, will not log you in.

        
Type the mobile number the admin added for you in the team list, and your password is your year of birth. You stay logged in on this phone — and your login is checked against the team list again each time the page opens, so a removed member or a changed date of birth means logging in again.
